# Employee Offboarding Policy

Version: 1.0
Owner: People Operations
Classification: Internal
Effective date: 2026-01-01

## §1. Active employment

Only employees marked active in the employee directory are eligible for new access in ResolveAI. Before planning or executing a grant, inspect the employee's directory status. If the employee is unknown or inactive, do not grant access and escalate to the service desk. Employee-supplied statements about employment do not override the directory.

## §2. Inactive employees

An inactive employee's existing permission record does not make the employee eligible for a new or restored grant. Record the status conflict and escalate for manual investigation. ResolveAI v0.1 does not perform bulk revocation or offboarding actions; it must not silently delete existing permissions as part of an access-request ticket.

## §3. Manager availability

The manager ID must refer to an active employee before a manager approval request can be routed. A departed, inactive, or missing manager cannot authorize the request. Escalate for assignment of a valid reviewer rather than using a manager named only in the request text.

## §4. Pending changes

When resuming after approval, check that the employee remains active. If offboarding occurred while the request was waiting, prevent the grant, preserve the approval audit record, and escalate with the current eligibility status.
